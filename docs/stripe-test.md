# Stripe テストモードの試し方

テストモードでは、本物の Stripe の決済ページを使いますが、お金は動きません。Stripe の審査も要りません。

## 1. キーを入れる

1. Stripe のダッシュボードで「テストモード」になっていることを確かめる
2. 「開発者」→「API キー」から **シークレットキー（`sk_test_…`）** をコピーする
3. プロジェクトの直下に `.env.local` を作り、次の1行を書く（このファイルは git に入りません。キーはチャットに貼らないでください）

   ```
   STRIPE_SECRET_KEY=sk_test_ここにキー
   ```

4. 開発サーバーを起動し直す（`npm run dev`）。画面上部の帯が「Stripe のテストモードで動いています」に変われば準備完了。キーを変えたときも、起動し直す（本番ではビルドし直す）

本番のキー（`sk_live_…`）を入れても、`STRIPE_ALLOW_LIVE=1` を明示しない限り決済は動きません（デモのまま）。本番に必要な仕組み（下の「まだ入っていないこと」）がそろうまでは使わないでください。

公開可能キー（`pk_test_…`）は使いません（決済ページは Stripe 側の画面を使うため）。

## 2. 支払い方法を有効にする（任意）

ダッシュボードの「設定」→「決済手段」で、コンビニ払い・PayPay などを有効にすると、All-in のプロジェクトの決済ページに出ます。All-or-Nothing はカード（Apple Pay / Google Pay を含む）だけです。

## 3. 試すこと

| 試すこと | 操作 | 確かめる場所 |
|---|---|---|
| All-in の支援 | NEON KAIJU など All-in のプロジェクトで支援 → カード `4242 4242 4242 4242` | マイページに「決済済み」、Stripe の「支払い」 |
| All-or-Nothing の支援 | 星空ラジオなど All-or-Nothing のプロジェクトで支援 → カードを登録 | マイページに「決済予定（目標達成後）」。この時点で請求なし |
| 目標達成後の請求 | マイページの「（テスト）目標達成として請求」 | 「決済済み」に変わる。Stripe の「支払い」に請求が出る |
| 本人認証が必要なカード | All-or-Nothing で `4000 0027 6000 3184`（毎回 3Dセキュアが必要） | 登録のときに認証画面が出る。後から請求すると「本人認証が必要なため…」になる |
| 後から請求が失敗する | All-or-Nothing で `4000 0000 0000 0341`（登録は成功、請求で失敗） | 「目標達成として請求」で、カードで決済できなかった旨が出る |
| 決済の失敗 | All-in で `4000 0000 0000 9995`（残高不足） | 決済ページでエラーになり、支援は記録されない |
| コンビニ払い | All-in で、決済ページの「コンビニ」を選ぶ（ダッシュボードで有効にしておく） | 完了画面とマイページに「払込票を開く」と支払期限。Webhook がまだないので、マイページは「お支払い待ち」のまま |
| キャンセル | 決済ページの「戻る」 | 確認の手順に戻り、「お支払いはキャンセルされました」と出る |
| メンバーシップ | アーティストのページからプランに加入 | マイページのメンバーシップ、Stripe の「サブスクリプション」 |
| 解約・再開 | マイページで解約 → 再開 | Stripe のサブスクリプションが「期間終了時にキャンセル」になり、再開で戻る |
| 上位プランへの変更 | 加入中に上位のプランを選ぶ | Stripe のサブスクリプションの価格が変わる（月額は次の更新日から） |
| 下位プランへの変更 | 加入中にプラン変更を開く | Stripe で加入した場合は「下位への変更は準備中」で選べない（Subscription Schedule が入るまで） |

有効期限は未来の日付、セキュリティコードは任意の3桁、郵便番号などは任意で構いません。

## まだ入っていないこと（本番の前に）

- **Webhook**：支援・加入の記録は、今は決済ページから戻ったときにサーバーで確かめて、ブラウザに保存している。本番では Supabase に保存し、`checkout.session.completed` などの Webhook で記録する（コンビニ払いの入金確認もここで受ける）
- **目標達成時の一括請求**：本番では募集終了時に、サーバーの定期処理がまとめて請求する。失敗した人には支払いのお願いを送る
- **下位プランへの変更**：次の更新日からの切り替えを Subscription Schedule で予約する（今は、Stripe で加入した人には選べないようにしている）
- **同じアーティストへの二重加入の防止**：本番では Customer をユーザーにひも付け、加入中の契約があれば新しく作らない
- **アーティストへの振込**：Stripe Connect（本人確認・口座登録・手数料を引いた送金）
- **ログイン**：今は決済の ID を持っている人だけが解約などをできる形。本番では Supabase Auth で本人を確かめる
