### 見送った指摘と理由

デモ（決済とデータベースが未接続）の段階では直せない、または直す効果が小さいもの。Supabase・Stripe を入れるときに対応する。

- **支援者限定の本文がページのデータに入っている**（code-security）：デモはサーバーがないため、本文をブラウザで出し分けている。本番では支援を確かめてからサーバーで返す（backers-only.tsx に TODO）
- **配送先の住所の全文がブラウザに渡る**（code-security）：モックのみ。本番では一覧は都道府県まで、CSV はサーバーで認証つきで作る（shipment-table.tsx に TODO）
- **ログイン（マジックリンク）が別のタブで開くと、支援の入力途中の内容が戻らない**（ux）：sessionStorage はタブごとのため。Supabase 導入時に、期限付きの保存か、6桁のコードを入力する方式、またはサーバーに下書きを保存する方式にする
- **AI校正 API の認証と、複数台での回数制限**（code-security）：今はメモリ上の簡易な制限と送り元のチェック。本番ではログイン中の実行者だけに限り、回数は Vercel KV などで数える
- **加入時のメールアドレスの確認**（code-security）：本番ではマジックリンクで確認してから月額課金を始める（join-flow.tsx に TODO）
- **郵便番号からの住所の自動入力**（ux）：外部の住所検索 API が必要
- **状態色（成功・警告・エラー）のテーマ化、見出しの書き方の統一**（visual）：見た目の破綻はなく、支援の流れを妨げないため公開後に
- **画像のサムネイル用の縮小版、フォントのウェイトの絞り込み**（seo）：表示速度の改善。静的書き出しでは画像の自動最適化が使えないため、本番（Vercel）に移すときに見直す
- **ソロのアーティストを構造化データで Person にする**（seo）：データに「ソロかグループか」を持たせる必要がある
- **デモのサイトを検索エンジンに出さない設定**（seo）：本番を公開するときに判断する
- **流れ続ける演出を止めるボタン**（a11y）：マウスやキーボードで乗せると止まる対応はした。全体を止めるボタンは公開後に検討
- **本番の手順**：Vercel の Production と Preview の両方に `NEXT_PUBLIC_SITE_URL` が必要（未設定だとビルドが止まる）。決済とデータベースをつないだら `NEXT_PUBLIC_DEMO=0` でデモの帯を消す
